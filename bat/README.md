# cfhk 优选线路 · bat 版（PowerShell 内核）

把 `cf_pin.py` 的测量口径与判定规则搬到 Windows 自带的 PowerShell 上，
做成双击即用的三选项工具。**不需要 Python、不需要 Node、不需要装任何东西。**

与 `cf_pin.py` 的区别是「形态」而不是「口径」：同一个候选池思路、同一套
20 秒采样窗口与超时惩罚、同一套「先淘汰再排序」、同一个 hosts 标记段格式
（逐字节一致），所以两者可以互相接管——脚本写的段 bat 能读，bat 写的段脚本也能识别。
但**两边同时跑会互相覆盖，同时只用一个**。

## 文件

| 文件 | 作用 |
|---|---|
| `cfpin.bat` | 入口。双击运行，三个选项 |
| `cfpin.ps1` | 菜单、三个动作、常驻循环 |
| `cfpin-core.ps1` | 内核：候选池、探测（内嵌 C# 编译的网络原语）、判定、hosts 读写 |
| `data/config.json` | 配置 |
| `data/state.json` | 轮换指针 + 最近 24 小时切换记录（首次运行后生成） |
| `cfpin.log` | 运行日志（首次运行后生成） |

## 三个选项

**1 执行一次测速并展示结果**

粗筛 56 个候选（TCP 只判存活）→ 读它们的落地机房 → 实测 12 个候选，
每个跑满 20 秒窗口。只显示，**不改 hosts**。表尾给出「若写入会写哪两个」。

实测时收到 4xx/5xx（典型是 CF `403 + error code: 1034`，即该边缘不服务这个
zone）的候选会标成「不服务」直接排除：那不是「慢一点」，写进 hosts 打开就是
错误页，所以既不进推荐位，也不做「全部偏慢时降级写」的兜底。

**2 测速并自动写入 hosts**

同上测一遍，写前对**探测域名**逐个候选做**真实证书链 + 主机名校验**（还会确认这个
边缘真的在为该 zone 服务，避免 `error code: 1034` 那种「证书正常但拒绝服务」的
IP 被写进去）。通过校验的按优劣写 1~2 个到 hosts 的 `CLOUDFLARE-PIN` 标记段，
写完刷新 DNS。

备份只在**第一次改写 hosts 之前**做一次（复制为 `hosts.bak`），之后不再覆盖；
hosts 的编码也保持原样（GBK/ANSI、UTF-8 含 BOM、UTF-16 都能逐字节写回）。
如果 hosts 里的标记段不完整（BEGIN/END 不成对），写入会直接失败并提示先手工修复，
不会连带删掉标记段之后的条目。

写入的域名是「探测地址 ∪ `writeAddresses`」：`open-design.ai` 这类**只写不测**的
域名不参与测速（少一份噪声、不拖慢一轮），但会和探测域名用**同一个 IP**写进标记段。

**3 常驻检测和切换**

默认档：

| 项 | 值 |
|---|---|
| 当前线路采样 | 3 秒一次 |
| 候选并发 | 1 |
| 一轮候选 | 12 ÷ 1 × 25 秒 ≈ 5 分钟 |
| 候选轮间隔 | 5 分钟 |
| 切换阈值 | 150ms |
| 探测地址 | `amr-link.open-design.ai` |
| 写入地址 | `amr-link.open-design.ai`、`open-design.ai`（后者只写不测） |

判定规则：候选 p50 比当前低 ≥ 150ms 才切；全都在丢包时退到「最不坏」的一条，
但要求它的丢包率不高于当前；当前读数样本不足（<3 且丢包 <50%）时判「观察中」不写；
**没有每日切换次数上限**，也没有「连续 N 轮」「回切冷却」这些阻尼。

常驻模式跑起来后，当前线路每 3 秒重新采样一次并打印一行状态：

```
  当前 104.17.141.1（SJC） p50 672ms  丢包 0.0%  |  观察中：最优候选快 29ms，未达阈值
```

## 两组地址：探测 vs 写入

配置里是**两个键**，职责分开：

| 键 | 参与什么 |
|---|---|
| `addresses` | 候选读数（p50/p95/丢包）、写前证书闸门、「当前线路」采样与判定基准 |
| `writeAddresses` | 只参与写入：和选中的 IP 一起写进标记段，不测速、不影响名次 |

实际写进 hosts 的是两者**并集**（去重、保序）。所以把 `open-design.ai` 放
`writeAddresses` 就够——它会和 `amr-link` 用同一个 IP 写进去，但不会让每轮
测速多跑一倍采样。

`addresses[0]` 是「当前线路」的采样目标，放 `amr-link.open-design.ai`
（客户端的 API 走它，用户体感以它为准）。

## 候选池（56 个，全部已实测确认机房）

| 段 | 数量 | 机房 |
|---|---|---|
| `104.17.128–159`（主机位 `.1`，全段） | 32 | SJC |
| `104.26.0/2/4/6/8/10/12/14`（主机位 `.1`） | 8 | HKG |
| `162.159.128–158` 偶数（主机位 `.1`） | 16 | HKG |

不扫 `162.159/16` + `104.26/16` 的 256 个地址：那两段里大部分落 LAX，
扫一遍要 6 秒，扫出来的东西也会在「读机房」那步被过滤掉。现在粗筛约 1 秒。

为什么候选池里要有 SJC（而不是只留 HKG）：`amr-link` 的回源在美西，边缘挂 HKG
等于让请求多绕一次跨太平洋往返。实测 `Server-Timing: cfEdge;dur=9,cfOrigin;dur=232`
——边缘自己只花 7~9ms，回源要 232ms。SJC 段 `104.17.128-159` 是扫遍 24 个 CF /16
共 768 个地址后确认唯一含 SJC 的段（32/32 全 SJC，边界干净）。

## 测量口径

与 `cf_pin.py` 一致，每一项都是实测校准出来的：

| 项 | 值 | 理由 |
|---|---|---|
| 采样窗口（候选） | 20s 硬上限 | 约 40 个样本，p95 才代表「1/20 的偶发卡顿」 |
| 采样窗口（当前 IP） | 自适应，1.2s 起，上限 `采样间隔 − 500ms` | 按上一拍 p50 外推，正好装下 3 个样本 |
| 单次 HTTPS 超时 | 1.5s | 完整请求正常约 500ms；用 TCP 的 0.3s 会把健康请求全误判成超时 |
| 超时记账 | 按 999ms 计入样本，不丢弃 | 丢弃会让「10 次卡 1 次」的 IP 看起来完美 |
| 淘汰 | 超时 ≥ 3 次，或丢包 ≥ 7.5% | 「慢」和「断」是两件事 |
| 排序 | 先档位（clean/ok/degraded），同档按 p50；p50 相同再按 p95 | p50 跨窗口极差 7ms，p95 是 220ms——p95 只做 tiebreak |
| TCP | 只做存活粗筛 | 8 个 IP 的 TCP 全在 78~103ms，HTTPS p50 却是 257~385ms |

**为什么「连不上」要重试一次**：SJC 有按 IP 分化的 SYN 挂死（实测 `.140` 达 20–35%，
`.128` 仅 0–5%），但挂死后立刻重试实测 7/7 全部成功。所以连接层失败重试一次，
仍失败才计丢包；只要这一轮重试过，最高只给 `ok`，永不给 `clean`——「一次都没卡过」
这个评价必须留给一次都没卡过的线路。

## 环境变量（只在自查时用，日常不用管）

| 变量 | 作用 |
|---|---|
| `CFPIN_HOSTS_FILE` | 把 hosts 指向别的文件，不碰真实系统 hosts |
| `CFPIN_FAST` + `CFPIN_WINDOW_MS` | 把 20 秒采样窗口压短，快速跑一遍全流程 |
| `CFPIN_ROUND_INTERVAL_MS` | 临时改候选轮间隔 |
| `CFPIN_MAX_ROUNDS` | 跑够几轮就退出常驻 |
| `CFPIN_ASSUME_BOOTSTRAP` | 冷启动时不再询问，直接按第一轮结果固定 |

## 实测

在这台机器上跑过的完整链路（真实网络，非模拟）：

```
① 粗筛 56 个候选（TCP 只判存活）… 完成：存活 56 个（1s）
② 读 56 个的落地机房…            完成（10s）    → SJC 32 + HKG 24，无一落远端
③ 实测 12 个候选 × 1 个域名…      完成（14s）

#    候选 IP          机房      p50      p95   丢包   档位
1    104.17.140.1 *   SJC     684ms    782ms   0.0%   健康
2    104.17.153.1     SJC     700ms   1538ms   0.0%   健康
...
结论：104.17.140.1 比当前快 21ms，未达切换阈值 150ms（不值得换）
```

## 注意

- 改写 hosts 需要管理员权限，bat 会自己请求提权（UAC 窗口点「是」）。
- 写前只校验证书，不做二次确认——按下就是执行一次。
- hosts 只能做「按顺序尝试」，没有真正的故障转移，所以默认只写 2 个。
- 浏览器开了 DoH 会绕过 hosts，配好了还慢就去关掉「安全 DNS」。
